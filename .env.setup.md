# Environment Variables Setup Guide

This document explains how to configure environment variables for local development.

## ⚠️ Important: Never Commit `.env` Files

- `.env` files contain secrets and credentials
- They are **NEVER** committed to version control
- `.gitignore` is configured to prevent accidental commits
- Each developer must create their own `.env` files locally

## Frontend Setup

### File: `frontend/.env.local`

Copy from `frontend/.env.example`:

```bash
cd frontend
cp .env.example .env.local
```

Edit `.env.local` and update values:

```env
VITE_API_URL=http://localhost:8000
VITE_API_TIMEOUT=30000
VITE_ENV=development
VITE_ENABLE_ANALYTICS=false
VITE_ENABLE_LOGGING=true
```

**Note:** Vite requires all client-side variables to be prefixed with `VITE_`.

Access in code:
```typescript
const apiUrl = import.meta.env.VITE_API_URL
```

## Backend Setup

### File: `backend/.env`

Copy from `backend/.env.example`:

```bash
cd backend
cp .env.example .env
```

Edit `.env` and update with your actual values:

```env
ENVIRONMENT=development
DEBUG=True
API_HOST=0.0.0.0
API_PORT=8000
API_TITLE=AI Assistance Platform
DATABASE_URL=postgresql://user:password@localhost:5432/ai_assistance
AZURE_SUBSCRIPTION_ID=your-subscription-id
AZURE_RESOURCE_GROUP=your-resource-group
AZURE_REGION=eastus
OPENAI_API_KEY=your-openai-api-key
OPENAI_MODEL=gpt-4
LOG_LEVEL=INFO
LOG_FORMAT=json
```

**Required before running:**
1. Database must be accessible or configured
2. OpenAI API key must be valid
3. Azure credentials (if using Azure services)

Access in Python:
```python
import os
api_url = os.getenv("API_URL")
api_key = os.getenv("OPENAI_API_KEY")
```

## Environment-Specific Files

### Development

- **Frontend:** `.env.local` (ignored by git)
- **Backend:** `.env` (ignored by git)

### Production

Never use `.env` files in production. Use:
- Docker environment variables
- Cloud platform secrets (Azure Key Vault, AWS Secrets Manager, etc.)
- Environment-specific configuration management

## Checking `.gitignore`

Verify `.env` files are ignored:

```bash
# Root .gitignore
git check-ignore .env
git check-ignore frontend/.env.local
git check-ignore backend/.env
```

If not ignored, the files will need to be added to `.gitignore`.

## Git Safety Tips

Before committing, check for accidentally staged secrets:

```bash
git status  # Check for .env files
git diff --cached  # Review staged changes for secrets
```

If you accidentally commit a secret:
1. **Immediately revoke** the compromised credential
2. **Never** force-push to remove it (it's still in history)
3. Use `git-filter-repo` or similar tools to clean history
4. Rotate all affected credentials

## Common Issues

**Issue:** Changes to `.env` appear in git status
```bash
# Solution: File was tracked before .gitignore was added
git rm --cached .env
git rm --cached frontend/.env.local
git rm --cached backend/.env
```

**Issue:** Variables not loading in development
```bash
# Frontend: Ensure prefix is VITE_ and restart dev server
# Backend: Ensure file is named .env (not .env.local or .env.example)
```
